# Blind null-world diagnostic protocol

Date frozen: 2026-09-01, before generating the null-world request or obtaining an LLM response.

Status: one-case development diagnostic. It is not a benchmark, confirmatory experiment, or estimate of a model-wide false-discovery rate.

## Question

When the anonymous observations are generated by the public two-field family with measurement noise but no extra process, does the same hypothesis prompt still produce an additional-state explanation, and can that explanation outperform both the fitted public baseline and every proposed state-free competitor on untouched conditions?

The LLM receives only the generated `prompt.txt`. It is not told that this is a null case and receives no repository or tool access. The prompt, response schema, model, reasoning effort, and isolation procedure match the retained positive development screen.

## Frozen measures

1. Count how many of the three proposals contain an additional state. Proposal alone is not counted as a false discovery because the task explicitly asks for competing explanations.
2. Fit every proposal independently on the null training conditions using the already implemented deterministic search budget.
3. Score on the same untouched null held-out condition definitions used by the positive screen.
4. Record a **false-attribution warning** only if the best additional-state proposal has at least 10% lower held-out RMSE than both:
   - the fitted public two-field baseline; and
   - the best proposed state-free model.

The 10% threshold is a development relevance rule, not a statistical significance level. Adding a state is never rewarded directly.

## Decision

This diagnostic cannot rescue the positive hidden-state route, which already failed its frozen discrimination experiment. Its role is explanatory:

- if the warning fires, record that the prompt/evaluator can manufacture a convincing hidden-state false positive and stop using it for mechanism recovery;
- if it does not fire, record only that this one null case did not expose that failure;
- do not tune the prompt, fit budget, threshold, or held-out cases after observing the answer.

Broader LLM benchmarking requires a separately frozen multi-world, multi-model protocol and a non-LLM structure-search baseline. It is not authorized by a favorable result here.
